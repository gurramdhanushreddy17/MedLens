# MedLens — AI-Powered Clinical Information Intelligence

MedLens is a full-stack clinical intelligence web application that consolidates fragmented medical data (patient-provided symptoms/conditions/medications and uploaded lab reports) into a unified, traceable clinical record with AI-generated plain-language summaries.

---

## 🏛️ Core Principles & Non-Negotiables

1. **Informational Only**: MedLens organizes, explains, and highlights patterns in medical records. It never issues diagnoses, makes definitive clinical determinations, or recommends treatments.
2. **Three-Tier Provenance**: Every piece of data displayed visually indicates its origin:
   - `user-entered` (unbordered): Directly input by patient or clinician.
   - `ai-extracted` (teal left border `#1D6E78`): OCR/LLM extracted from source lab documents.
   - `ai-generated` (violet left border `#6B5CA5`): Generated by AI summarization.
3. **Traceability**: Every lab result points directly back to its source document, extraction confidence, and date.
4. **Mandatory Disclaimer**: AI summaries always display an immutable disclaimer:
   > *"This summary is for informational purposes only and organizes existing record data. It is not a medical diagnosis. Please consult a qualified healthcare professional."*

---

## 🛠️ Tech Stack

- **Framework**: Next.js 14 App Router (React 18, TypeScript 5)
- **Styling**: Tailwind CSS with custom clinical design tokens (`ink`, `paper`, `surface`, `line`, `accent`, `flag-high`, `flag-low`, `flag-normal`, `ai-generated`)
- **Typography**: Source Serif 4 (Headings), Inter (UI), IBM Plex Mono (Lab Values & Numbers)
- **Database & ORM**: PostgreSQL via Prisma 5.22.0
- **Authentication**: NextAuth.js (Credentials Provider with bcryptjs, role-based access for `clinician` and `admin`)
- **LLM Integration**: Google Gemini 2.5 Flash via official `@google/genai` SDK (server-side only, strict JSON mode & validation)
- **Document Processing**: `pdf-parse` for text PDFs, `tesseract.js` WASM OCR fallback for scanned images
- **Export**: `@react-pdf/renderer` for standardized PDF reports
- **Charts**: `recharts` for multi-date test trend visualization
- **Testing**: `vitest` unit test suite for deterministic clinical logic

## 🚀 Getting Started

### 1. Prerequisites
- Node.js 18.x or 20.x
- PostgreSQL instance (Neon, Supabase, or local PostgreSQL)
- Anthropic Claude API Key

### 2. Configure Environment Variables
Copy `.env.example` to `.env`:
```bash
cp .env.example .env
```
Fill in the values:
```env
DATABASE_URL="postgresql://username:password@host:5432/medlens?sslmode=require"
NEXTAUTH_URL="http://localhost:3000"
NEXTAUTH_SECRET="your-generated-random-secret"
ANTHROPIC_API_KEY="sk-ant-..."
```

### 3. Database Migration & Seed
Run Prisma migrations to create the database schema and populate with rich synthetic patient data:
```bash
npx prisma migrate dev --name init
npm run seed
```

### 4. Run Development Server
```bash
npm run dev
```
Open [http://localhost:3000](http://localhost:3000) in your browser.

## 🩺 Synthetic Patient Test Scenarios

The seed dataset contains 3 distinct patient profiles designed to validate every edge case:

1. **Sarah Mitchell (47F)**:
   - Chronic diabetes + hypertension patient.
   - **3 medical reports across 4 months** with 14 lab results.
   - Demonstrates **multi-date trend charts** for Glucose, HbA1c, and Creatinine.
   - Includes **missing reference range handling**: TSH and Free T4 from April show *"No range provided"* rather than hallucinated ranges.

2. **James Okafor (62M)**:
   - Cardiovascular profile with intentional **value conflict**:
   - Two lipid panels from LabCorp and Quest Diagnostics on the same date (2025-02-10) with conflicting LDL Cholesterol values (`88 mg/dL` vs. `112 mg/dL`).
   - Triggers the **ConflictBanner** with automated inconsistency detection.
   - Includes clinician clarification response on record.

3. **Elena Vasquez (34F)**:
   - Reproductive endocrinology and infectious disease panel.
   - Demonstrates **qualitative lab results** (`HIV Antibody: Negative`, `Rubella IgG: Reactive`) handled via separate semantic path (flagged `unknown`, not converted to numbers).

## 🧪 Testing

Run the deterministic test suite:
```bash
npm run test
```
Runs 37 unit tests covering:
- Pure reference range computation (`computeFlag` logic for high/low/normal/unknown bounds)
- Qualitative value detection (`Negative`, `Positive`, `Reactive`)
- Multi-report conflict detection (same-date conflicts, duplicate tests, 7-day trend conflicts)
- De-duplication and null handling

To verify production compilation:
```bash
npm run build
```
